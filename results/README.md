# Try-On Results

19 real outputs from the deployed Deedar system. Nothing here is illustrative, mocked, or generated by a different tool.

Image files are in [`../assets/tryon/`](../assets/tryon/).

---

## How to read these

Every sample is a three-panel strip:

| Panel | What it is |
|---|---|
| **Left** | The shopper's input photo — wearing a *different* outfit |
| **Middle** | The catalog garment (a synthesised flat-lay, see [`../docs/dataset-construction.md`](../docs/dataset-construction.md)) |
| **Right** | The generated try-on output |

The left panel matters: the person arrives wearing something else entirely. The system has to remove that outfit and render the target garment on the same body, in the same pose, with the same face — which is why "the output looks like the middle garment on the left person" is the whole test.

### What to look for

**Identity preservation** — face, hair, body shape, skin tone and pose carried over from the left panel unchanged. If the output looks like a different woman, the system has failed at its core job.

**Garment length and silhouette** — the kameez should reach its real length. Truncation is the single most common failure of Western-trained try-on models on this clothing.

**Two-piece coupling** — kameez *and* trousers should both change together. Sample 13 is the clearest demonstration: the input has plain black trousers, the target has black-and-white circle-print trousers, and both pieces transfer.

**Texture fidelity** — embroidery, gota, mirror work and block print should survive. In this category texture *is* the product; a smoothed-out print is a wrong result even if the shape is right.

**Colour accuracy** — the garment colour should match the middle panel, not drift.

## Weak cases

Included deliberately rather than filtered out.

| File | What goes wrong |
|---|---|
| `16.jpeg` | **Colour drift.** The cream flat-lay renders as a pale yellow. Matches the documented synthetic-flat-lay colour-drift limitation. |
| `17.jpeg` | **Motif simplification.** A dense multicolour abstract print comes out with fewer, coarser motifs than the source garment. |
| `4.jpeg` | **Border detail loss.** The dense floral border band is partly flattened. |
| `9.jpeg` | **Length/hem.** The output kameez hem reads shorter than the flat-lay indicates. |

### What is absent from all 19 samples

**No dupatta.** Every sample is a kameez-and-trouser two-piece. This is consistent with the documented limitation — semi-transparent draped layers are the weakest case and are treated as a dedicated workstream, not something more training resolves. See [`../docs/limitations.md`](../docs/limitations.md).

Other conditions not represented here: off-frontal or seated poses, cluttered backgrounds, extreme lighting, and low-resolution uploads. All are documented as known sensitivities.

## Quantitative results

Metric figures, protocol and the current measured position: [`../docs/evaluation-protocol.md`](../docs/evaluation-protocol.md).

Summary: the fine-tuned model and the zero-shot base are **statistically tied on pixel metrics, with only a borderline perceptual improvement.** The samples above show the system working well in the common case; the metrics show the fine-tune has not yet separated from the base. Both statements are true, and the diagnosis and plan are in that document.
