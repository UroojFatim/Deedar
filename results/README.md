# Try-On Results

Real outputs from the deployed Deedar system. Nothing here is illustrative, mocked, or generated by a different tool.

---

## How to read these

Each result shows the three images that matter:

| Element | What it is |
|---|---|
| **Person input** | The shopper's uploaded full-body photograph |
| **Garment input** | The catalog garment image (a synthesised flat-lay — see [`../docs/dataset-construction.md`](../docs/dataset-construction.md)) |
| **Try-on output** | What the system generated |

### What to look for

**Identity preservation** — face, hair, body shape, skin tone and pose should come from the person input unchanged. If the output looks like a different person wearing the outfit, the system has failed at its core job.

**Garment length and silhouette** — the kameez should reach its real length. Truncation is the single most common failure of Western-trained try-on models on this clothing.

**Two-piece coupling** — kameez and trousers should read as one coherent outfit, not an upper-body patch over unrelated legs.

**Texture fidelity** — embroidery, gota, mirror work and block print should survive. In this category texture *is* the product; a smoothed-out print is a wrong result even if the shape is right.

**Colour accuracy** — the garment colour should match the catalog image, not drift.

## Weak cases

Failure cases are included deliberately rather than filtered out. See [`../docs/limitations.md`](../docs/limitations.md) for the full accounting; the short version of where output quality drops:

- **Dupatta present or prominent** — semi-transparent draped layers are the weakest case and currently the largest quality gap
- **Off-frontal or seated poses**
- **Heavy occlusion** of the garment in the source photo
- **Cluttered or low-contrast backgrounds**
- **Extreme or strongly coloured lighting**
- **Low-resolution or heavily compressed uploads**

A submission that shows only its best outputs invites exactly one question. We would rather answer it up front.
